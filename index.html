StrategyQA Multi-Agent Reasoning

LLM Debate and Judge Pipeline

Overview UI Results Method Analysis Prompts Repo Coverage Transcripts Report

Abstract

This project studies whether a structured multi-agent debate can improve yes/no reasoning on StrategyQA. Two LLM debaters first answer independently, debate only when they disagree, and then a judge selects the final answer from the transcript. The system is compared against Direct QA, Self Consistency, and a bonus three-judge jury panel.

Project Logic

The central idea is that adversarial discussion can expose weak assumptions that a single direct answer may hide. The final run shows debate is competitive with the baselines and produces inspectable transcripts for qualitative analysis.

Methods

The evaluation includes four methods: debate with a single judge, Direct QA, 9-sample Self Consistency, and a 3-judge jury panel. Accuracy and paired McNemar tests are computed from saved JSON logs.

Results

The saved 100-question StrategyQA run shows that the revised debate pipeline is competitive with the baselines and outperforms Direct QA in this run. Self-consistency achieves the highest accuracy. The goal was not only to maximize accuracy, but also to test whether adversarial interaction creates better evidence for a judge than a single direct answer.

Debate vs Jury Panel p = 0.3428

The jury panel completes the bonus extension but is lower than the single-judge debate result in this saved run.

Jury panel note: the implemented panel uses 3 independent LLM judges and majority vote. The jury logs contain 1 internal disagreement out of 100 questions and 5 cases where the panel answer differed from the single judge recorded during the jury run, so disagreement was too sparse to show a strong question-difficulty correlation.

The interpretation is cautious: debate improved substantially after prompt and logging fixes, and its difference from the baselines is not statistically significant in this 100-question run. This supports a practical lesson from multi-agent reasoning work: debate helps only when both agents produce reliable, parseable, non-empty arguments and the judge receives enough structure to compare them.

Methodology

The implementation follows the assignment's four-phase debate protocol and keeps agent behavior, prompts, configuration, logs, and evaluation separated into modules. The current model profile is selected through environment variables, while hyperparameters such as rounds, temperature, max tokens, adaptive stopping, and self-consistency samples live in config/config.yaml.

Phase 1: Initialization

Debater A and Debater B answer independently before seeing each other. Their initial responses are logged with extracted YES/NO labels.

Phase 2: Debate

If the initial answers disagree, the debate runs for up to 3 rounds. Debater A argues first, then Debater B responds after seeing A's current-round argument and the previous transcript.

Phase 3: Judgment

The judge receives the original question, initial positions, and all rounds. It must return analysis, strongest and weakest arguments, final answer, and confidence.

Phase 4: Evaluation

Predictions are compared with StrategyQA ground truth. The evaluator computes accuracy and paired McNemar tests against debate.

Implementation Details

  • agents/debater.py, agents/judge.py, and agents/jury.py implement the agents.
  • debate/debate_orchestrator.py controls initialization, consensus, rounds, judgment, and logging.
  • experiments/ contains runners for debate, direct QA, self-consistency, and the bonus jury panel.
  • evaluation/evaluate_accuracy.py reads JSON logs and prints the result tables used in this page.
  • app.py serves the web UI and exposes the live debate endpoint.

Prompt Engineering

Prompt design was iterated after inspecting failures in early logs. The first prompts were too loose: one debater sometimes produced no argument, judge outputs were hard to parse, and some answers were truncated before the final verdict. The final prompts use role framing, explicit answer labels, visible rationales, and strict judge output fields.

  • Role framing: Debater A is the proponent and Debater B is the opponent, but initial answers are not forced to fixed YES/NO stances.
  • Output constraints: Every debater response starts with Answer: YES or Answer: NO.
  • Round context: Debater B receives Debater A's current-round argument before responding.
  • Judge structure: The judge must include analysis, strongest arguments, weakest arguments, final answer, and confidence.
  • Baselines: Direct QA and self-consistency use separate prompts so their behavior is not accidentally debate-shaped.
